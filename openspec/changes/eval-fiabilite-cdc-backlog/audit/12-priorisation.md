# 4.2 — Priorisation P0/P1/P2 par gain fonctionnel

Change `eval-fiabilite-cdc-backlog`, tâche 4.2. Rang justifié par les
4 piliers (P1 Connaissance, P2 Diagnostic, P3 Veille, P4 Partage) et les
5 profils (Public, Décideur, Expert, Admin data, Admin plateforme).

## P0 — chaîne minimale de mise en service (gain décisif)

Socle données → restitution → confiance minimale (P1+P2+P4) :
import (US1.1–1.6) → catalogue pivots (enregistrer/consulter/alimenter) →
qualité socle (contrôles US2.1–2.3, complétude US2.4, qualification US2.5) →
référentiels BV/captages/PPE/indicateurs (EPIC 3 hors H3) → calculs simples
et agrégations (US4.1–4.3) → carte + couches de base + fiche territoire
(US6.1–6.4, US6.7, US6.21) → exports simples (US8.1 CSV, US8.6 vue simple) →
auth/rôles (US9.1–9.3) → traçabilité imports/calculs (US10.1/10.2).
Seuils US7.1 en P0 **si** E1 tranché vers MVP, sinon P1.

## P1 — utile, lot 2 (robustesse, confort, gouvernance)

EPIC 5 AMC complète (US5.1–5.6) et US7.5 associée (option à lotir, cf. M2) ;
sélecteur avancé (restes G1 : facettes, presets, fonds) ; catalogue avancé
(recherche/filtres) ; API US8.5 ; rapport PDF US8.3 ; partage par lien US8.4 ;
maille H3 (US3.4) ; alertes seuils/changements (US7.2/US7.4) ; qualité
avancée (US2.6/2.7). Motif : nécessaires à l'usage courant mais non
bloquants pour le premier diagnostic BVAEP partageable (P4).

## P2 — lambda, à ne pas détailler (critère de réactivation entre parenthèses)

- Gadgets de sélecteur (ex. US6.20 fonds de carte, US6.13 presets) ;
- Métadonnées avancées non bloquantes (ex. US1bis.14/15) ;
- Audit d'usages détaillé (US10.6), adaptation d'interface (US9.5), suivi
  des connexions (US9.6).
- Mention obligatoire : « à ne pas détailler » — réactivation si lot 2
  validé par la MOA ou seuil d'usage partenaire atteint.
